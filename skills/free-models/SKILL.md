# Free models via Our Free Model

This plugin runs a local gateway that serves free frontier models with no
account and no API key. There are two ways to reach them, and picking the right
one matters.

## The two lanes

**As a model provider.** `[model_providers.our-free-model]` in `~/.codex/config.toml`
points Codex at the gateway, and the gateway's catalog puts the free models in
Codex's own model picker. This is the normal path: select the model, use it for
the whole session, and it behaves like any other provider.

**As tools.** Three MCP tools reach the same lane without changing the session
model:

- `list_free_models` — the current roster.
- `ask_free_model` — one question to one model, returns its answer.
- `gateway_status` — is the gateway up, where, and serving how many models.

## When to use which

Use `ask_free_model` when the answer is a single self-contained question and the
user does not want the session's context sent to a second model: a second
opinion on a design choice, a quick factual check, a translation, a short
summary of text already in the conversation.

Do **not** use it to delegate work that needs the repository. `ask_free_model`
sends only the prompt you give it — no files, no conversation history, no tools.
A model reached this way cannot read the codebase, run a command, or edit a
file. If the task needs any of that, the work belongs in the session itself, on
a free model selected as the provider.

## Diagnosing a failure

The free lane is a shared public pool, so two failures are normal and neither is
a bug in this plugin:

- **`Free usage limit reached` (HTTP 429).** The lane's per-egress quota is
  spent, and the message carries a retry-after. This is not a configuration
  problem and there is nothing to fix; the free models become available again
  when the window resets.
- **`RegionError` (HTTP 403).** The lane refuses this network egress. A
  different network, or a proxy, changes the verdict.

Run `gateway_status` first. If it reports the gateway is not set up, the user
needs `npx codex-our-free-model setup` (or `cofm setup`) — that starts the
gateway and writes the provider block. If it reports the gateway is configured
but silent, the `cofm run` process is not running.

Never edit `config.toml` by hand to fix this. The provider block is
marker-delimited and regenerated by `cofm setup`; hand-edits inside it are
overwritten. `cofm doctor` checks the whole install and reports which part is
actually broken.
